# التحقق من عنوان Expo العام خلف Replit

التاريخ: 2026-10-15. النطاق: تصحيح عنوان التطوير فقط.

## التغيير الوحيد في التشغيل

أضيف إلى بداية أمر Workflow الحالي `Masarak preview`:

```sh
EXPO_PACKAGER_PROXY_URL="https://$REPLIT_DEV_DOMAIN"
```

احتُفظ بأعلام التشغيل والمنفذ والـWorkflow نفسه؛ لا تغيير في `app.json` أو الحزم أو روابط Auth أو الصلاحيات. جرى التعديل عبر واجهة إعداد Workflows ثم إعادة التشغيل مرة واحدة. القيمة توسع عند بدء العملية، وليست عنوانًا ثابتًا أو إعدادًا داخل dotenv يتجاهله Expo في هذه الحالة.

## الدليل قبل وبعد

| الفحص | قبل | بعد |
| --- | --- | --- |
| Android manifest | HTTP 200 | HTTP 200 |
| iOS manifest | HTTP 200 | HTTP 200 |
| GET رابط الفتح المولّد لكل منصة | HTTP 200؛ عنوان داخلي ومنفذ 5000 | HTTP 200؛ عنوان Replit العام والمنفذ الافتراضي |
| رابط حزمة Android المولّد | HTTPS مع منفذ خارجي 5000؛ HTTP 502 | HTTPS على عنوان المعاينة العام؛ HTTP 200 وJavaScript |
| رابط حزمة iOS المولّد | HTTPS مع منفذ خارجي 5000؛ HTTP 502 | HTTPS على عنوان المعاينة العام؛ HTTP 200 وJavaScript |
| SDK المعلن | 57.0.0 | 57.0.0 |

وقت دليل «قبل»: `2026-10-15T00:45:08.449Z`.

وقت دليل «بعد»: `2026-10-15T00:45:41.526Z`.

الاختبار استخدم `manifest.launchAsset.url` كما رجع من Expo دون إعادة كتابة البروتوكول أو المضيف أو المنفذ أو المسار أو معاملات الطلب. فحص GET إلى `/_expo/open` لا يفتح محاكيًا أو جهازًا؛ قرأنا الرابط الناتج وتحققنا من مضيفه ومنفذه.

## إعادة الفحص والأدلة المحلية

```sh
node scripts/check-expo-public-url.mjs after
```

- `generated-artifacts/expo-proxy/before.json`
- `generated-artifacts/expo-proxy/after.json`

ملفات JSON محلية متجاهلة من Git، ولا تحتوي على مفاتيح أو محتوى حزم التطبيق. لا تُحفظ حزم JavaScript الكبيرة في المستودع؛ هذا الملخص والاختبار محفوظان في Git المحلي.

## حدود النتيجة

- نجحت فحوص `node --check` و`expo lint` و`tsc --noEmit`، وبقيت صفحة الاستعادة ظاهرة بصورة سليمة في معاينة الويب بعد إعادة التشغيل.
- ظهر تحذير انقطاع Metro في جلسة المتصفح القديمة أثناء إعادة التشغيل؛ الالتقاط الجديد بعد التشغيل عرض الصفحة دون خطأ. لا يُعد ذلك اختبارًا لجهاز أصلي.
- ثبت زوال خلل عنوان الاتصال الذي تسبب في HTTP 502 لحزم المنصتين.
- لم يُختبر فتح Expo Go على هاتف فعلي أو تشغيل الواجهة الأصلية أو العودة من البريد على جهاز.
- لا يثبت هذا حل أي مشكلة مستقلة في Safari أو توافق إصدار Expo Go أو نظام الهاتف.
- لم تُشغّل عملية EAS أو native build، ولم يُنشأ APK/IPA، ولم تُرقَّ الحزم أو يُنشر التطبيق أو تُرسل رسائل بريد.
- لا اتصال بـGitHub ولا push/pull أو مزامنة؛ الحفظ محلي فقط ونقطة الرجوع السابقة باقية في تاريخ Git.
