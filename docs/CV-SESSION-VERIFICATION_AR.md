# حماية تحليل السيرة بجلسة Supabase

## نطاق الإصلاح

- يقرأ العميل الجلسة الحالية قبل إنشاء طلب رفع الملف، ويرسل access token في `Authorization: Bearer` فقط.
- يتحقق الخادم من التوكن بالاتصال بخدمة Supabase Auth للمشروع عبر `GET /auth/v1/user` باستخدام مفتاح المشروع العام الحالي.
- لا يعتمد الخادم على فك JWT محليًا أو على `user_id` يرسله العميل، ولا يحتاج service-role.
- التحقق يسبق Multer واستقبال الملف في ذاكرة التطبيق واستخراج النص وطلب Groq.
- غياب/فساد ترويسة المصادقة أو رفض التوكن من Supabase يعيد 401.
- غياب إعداد التحقق أو تعذر الوصول إليه أو رده غير الصالح يعيد 503؛ لا يسمح باستكمال المعالجة.
- أضيف السماح بترويسة Authorization في preflight فقط، دون توسيع قائمة الأصول المسموح بها.
- فصل إنشاء تطبيق Express عن تشغيل المنفذ ليمكن اختباره على loopback مؤقت دون تشغيل خدمة عامة.

## دليل الاختبار المحلي

نجحت 21 حالة اختبار جديدة للعميل والخادم:

- غياب التوكن وصيغ Authorization الخاطئة تُرفض قبل فحص multipart.
- رفض Supabase لتوكن تالف/منتهي/مزور يعيد 401، دون استخراج أو تحليل.
- رد 403 من خدمة Auth يُعامل كتـوكن غير مقبول ويعيد 401.
- تعطل Auth، أو رد 500، أو رد بلا مستخدم، أو غياب الإعداد يفشل بصورة مغلقة.
- قبول جلسة محاكاة مع رفع ملف PDF موجود ضمن ملفات الاختبار واستخراج نصه محليًا.
- استدعاء التحليل في حالة القبول هو دالة محاكاة فقط، وليس اتصالًا بـGroq.
- هوية صاحب الطلب مصدرها رد Auth؛ حقل user_id المختلف في الطلب لا يغيرها.
- العميل يقرأ الجلسة لكل طلب، ويرسل التوكن المحدّث في الترويسة وليس حقول الملف.
- غياب الجلسة يمنع إنشاء طلب رفع أصلًا، ورد 401 لا يتحول إلى نتيجة تحليل.
- preflight يسمح بالترويسات اللازمة للأصول المسموح بها سابقًا فقط.

أمر الاختبارات الجديدة:

```sh
node --test server/cv-session.test.mjs tests/cv-api.test.cjs
```

نجحت أيضًا الاختبارات السابقة الـ42 للخادم، و`npm run lint` و`npx --no-install tsc --noEmit`.
الاختبارات تستخدم اتصالات HTTP على loopback فقط، وSupabase وGroq بمحاكاة؛ لم تُرسل سيرة أو بيانات إلى مزوّد خارجي.

**حد معروف خارج هذا الإصلاح:** خطأ multipart بلا boundary، بعد قبول المصادقة، ما زال يمر بمعالج الأخطاء العام ويعيد 500. الطلب نفسه دون مصادقة يعيد 401 قبل الوصول إلى المحلّل. لم نغيّر معالجة أخطاء الملفات ضمن مهمة المصادقة.

## ما لم يُفعّل أو يُختبر حيًا

- خادم التحليل لم يُشغّل للعامة، ولم تُضف مفاتيح أو تُغيّر عناوين HTTPS أو صلاحيات خارجية.
- نجاح هذه المحاكاة لا يثبت قبول جلسة حقيقية من Supabase أو نجاح التحليل من الواجهة.
- تشغيل الخدمة وربط HTTPS وتوفير مفتاح Groq ما زالت مهام منفصلة؛ ليست منفّذة بهذا الإصلاح.
- السيرة الوهمية التي سيقدمها المستخدم لم تُستخدم ولم يُنشأ بديل لها.
- اختبار الهاتف الفعلي معلّق إلى تجربة زميلة المستخدم، ولا يُعتبر ناجحًا.
