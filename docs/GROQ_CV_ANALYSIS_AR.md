# تحليل السيرة الذاتية عبر Groq

آخر تحديث: 23 أكتوبر 2026. يصف هذا الملف الربط المحلي بعد اختيار Groq، ولا يثبت أن الطلب الحي أو الحصة أو جودة المخرجات اختُبرت بعد هذا التغيير.

## النطاق المعتمد

يدعم FR3 رفع سيرة بصيغة PDF نصي باللغة الإنجليزية فقط، حتى 10 ميجابايت و15 صفحة. يتحقق الخادم من الجلسة والملف وموافقة المستخدم، ثم يستخرج PDF.js النص مع ترتيب الصفحات والأسطر. يرسل **النص المستخرج فقط** إلى Groq؛ لا يرسل ملف PDF نفسه إلى Groq. تعود النتيجة مسودة للمراجعة والتصحيح والاستبعاد ثم الاعتماد والحفظ. لا يدعم هذا المسار Word أو الصور أو OCR.

التقنيات: تطبيق Expo/React Native، وخادم Node.js/Express، وPDF.js، وGroq API عبر `openai/gpt-oss-120b` افتراضيًا، مع مخطط JSON منظم وقواعد تحقق محلية. بادئة `openai/` جزء من معرّف نموذج GPT-OSS؛ الاتصال يجري إلى Groq، ولا يستخدم OpenAI API. يدعم النموذج وضع JSON Schema الصارم بحسب [وثائق Groq](https://console.groq.com/docs/structured-outputs). التقرير يذكر Python في بند 3.7.1؛ استخدام Node.js/Express اختلاف تقني قرره الفريق ويجب أن يظهر بوضوح في تقرير Phase 2. مزود LLM لا يدرّب نموذج ML خاصًا بالمشروع.

## كيف نحد من الأخطاء

- يطلب النظام فصل المهارات والتعليم والمشاريع والخبرات والدورات والشهادات والأنشطة، وعدم اعتبار الجامعة أو الدرجة أو المسمى الوظيفي مهارة.
- يلزم كل سجل اقتباسًا حرفيًا مرتبطًا به من نص السيرة. يتحقق الخادم من وجود الاسم والجهة والوصف والتاريخ في الدليل المرتبط وبالقسم المناسب؛ القيم غير المسندة تُترك فارغة للمراجعة.
- يحتفظ الاستخراج المحلي بحدود الصفحة والسطر، ويتحقق من ارتباط التاريخ بالسجل. عند الشك لا يخمن تاريخًا أو جهة أو اسم مشروع.
- أسماء المهارات الصريحة تُستعاد محليًا عند سقوطها من رد النموذج، وتُطابق مع قاموس المهارات. لا يستنتج النظام الإتقان أو المهارات من السياق وحده.
- لا يوجد تحويل صامت إلى تحليل محلي كامل عند غياب Groq أو فشل الاتصال. تظهر رسالة خطأ، ولا تُعتمد المسودة قبل مراجعة المستخدم.

هذه الضوابط تخفض الأخطاء ولا تضمن استخراج كل تخطيط أو صحة كل تفسير؛ يجب على المستخدم مراجعة النتيجة قبل الاعتماد.

## إعداد الخادم

- المفتاح المطلوب: `GROQ_API_KEY` في `server/.env` محليًا أو Replit Secrets/متغيرات بيئة الخادم. يُستخدم مفتاح Groq نفسه لخيار تقييم المقابلة، لكن كل ميزة منفصلة وتتطلب موافقتها الخاصة.
- نموذج تحليل السيرة: `GROQ_CV_MODEL=openai/gpt-oss-120b` اختياري. هذا الإعداد خاص بالسيرة؛ `GROQ_MODEL` يبقى إعداد المقابلة.
- لا تضع المفتاح في `.env` الجذر أو أي متغير يبدأ بـ`EXPO_PUBLIC_`، ولا تحفظه في Git. لا حاجة إلى مفتاح Gemini لمسار تحليل السيرة بعد هذا التغيير.
- عند نقل الكود إلى جهاز آخر، أضيفوا المفتاح الخاص بكم إلى بيئة الخادم؛ لا تنسخوا ملف `.env` المشترك أو ترفعوا أي سر للمستودع.

## الخصوصية والاختبار

تقول [وثائق بيانات Groq](https://console.groq.com/docs/your-data) إن طلبات الاستدلال لا تُحتفظ بها افتراضيًا، وقد تُسجل بيانات مؤقتًا لأسباب موثوقية الخدمة أو إساءة الاستخدام لمدة تصل إلى 30 يومًا. وتذكر Groq أنها لا تستخدم بيانات العميل لتدريب نماذجها. راجعوا إعدادات وشروط الخدمة قبل إرسال بيانات شخصية. استخدموا سيرة اصطناعية أو منقحة للتجارب.

غيّر إصدار المحلل بعد التحويل؛ النتائج القديمة تظهر بحاجة إلى إعادة تحليل صريحة. لا يستبدل النظام بيانات معتمدة تلقائيًا.

## ما لم يُتحقق بعد

- لم يُرسل طلب Groq حي بعد هذا التحويل، ولم تُرسل سيرة حقيقية.
- يلزم اختبار تكامل بملف PDF اصطناعي أو منقح، ومراجعة الاقتباسات والصفحات وفصل الأقسام قبل اعتبار FR3 مكتملة.
- يلزم اختبار قبول الواجهة على Android وiOS وتحقق وجود `GROQ_API_KEY` في بيئة الخادم المستخدمة.
- حدود Groq تعتمد على الخطة والنموذج وقد يظهر HTTP 429؛ لا توجد حصة استخدام مضمونة أو غير محدودة.

كان هناك اختبار Groq حي قديم بتاريخ 21 أكتوبر 2026 لنموذج `openai/gpt-oss-20b` ومسار سابق. هذه نتيجة تاريخية ولا تثبت عمل الربط الحالي مع `openai/gpt-oss-120b`.
