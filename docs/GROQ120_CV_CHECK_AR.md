# سجل تاريخي: تحسين تحليل السيرة عبر Groq — 2026-10-21

هذا سجل تجربة سابقة قبل التحويل المؤقت إلى Gemini في 22 أكتوبر. توثيق الربط الحالي بعد إعادته إلى Groq في 23 أكتوبر موجود في `GROQ_CV_ANALYSIS_AR.md`؛ نتائج هذه التجربة لا تثبت عمل النسخة الحالية بعد التحويل.

## النطاق والتنفيذ
- PDF نصي إنجليزي فقط؛ لا OCR أو أنواع ملفات أو ميزات أخرى. لا تغيير Supabase أو قاعدة البيانات أو المصادقة.
- افتراضي **تحليل السيرة فقط** صار `openai/gpt-oss-120b`، عبر Groq API ومفتاحه الخادمي، لا OpenAI API.
- فحص إعدادات البيئة أظهر وجود `GROQ_API_KEY` وعدم وجود override محفوظ باسم `GROQ_MODEL`. الاختبار التشغيلي أكد أن النموذج الفعلي 120b؛ لم نضبط متغيرًا مشتركًا يغيّر نموذج المقابلة خارج النطاق.
- JSON Schema الصارم باقٍ: جميع حقول المزوّد مطلوبة و`additionalProperties:false`، مع تحقق خادمي مستقل. وثائق Groq الرسمية تؤكد دعم 120b لهذا النمط: https://console.groq.com/docs/structured-outputs
- طلب فصل كل تعليم وخبرة ومشروع في سجل مستقل مع دليل متعدد الأسطر لسجله فقط. توسيع دليل التعليم مقيد بسجل محلي وحيد يطابق المؤهل، وليس بأي جامعة موجودة في القسم. يمكن استكمال الحقول الفارغة من هذا السجل الحرفي فقط؛ عند الالتباس لا يُستكمل الربط.
- فحص نهائي لاقتباسات كل حقل، وإفراغ القيم غير المسندة للمراجعة. بيانات صفحات اختيارية `field_pages` مشتقة من إحداثيات PDF، لا من ادعاء النموذج؛ تُعرض بجوار دليل الحقل. لا رقم صفحة عند تعذر تحديده بشكل موثوق.
- عقود الحقول الموجودة كما هي، مع بيانات صفحات اختيارية متوافقة رجعيًا؛ لا مخطط قاعدة بيانات جديد. المراجعة والتصحيح والاعتماد باقية، وإصدار المحلل الجديد يفعّل مسار إعادة التحليل الصريح دون استبدال تعديلات المستخدم تلقائيًا.
- غياب المفتاح = 503 واضح؛ عدم توفر النموذج/توافق المخطط = خطأ واضح دون مزوّد آخر أو fallback محلي. تحديث نص الموافقة والحدود ليطابق التشغيل الفعلي.

## دليل تشغيل حقيقي محدود
- طلب خارجي **واحد فقط** على PDF تركيبي جديد خالٍ من بيانات المستخدمين، باستخدام مكوّن التحليل الفعلي مباشرة، دون تجاوز مسار HTTP المحمي.
- Groq HTTP **200**؛ النموذج المطلوب والمُعاد `openai/gpt-oss-120b`؛ `finish_reason:stop`.
- النتائج: مهارتان، تعليم واحد، مشروع واحد، خبرة واحدة، دورة واحدة، شهادة واحدة.
- تحقق اسم الجامعة والمؤهل والتخصص وسنة التخرج واسم المشروع. اقتباسات جميع الحقول المرتجعة موجودة حرفيًا في النص؛ تحقق مصدر صفحة الجامعة.
- لا إرسال لسيرة شخصية أو مقتطف المستخدم السابق، ولا طلبات تشغيل إضافية تلقائية.

## الاختبارات والقيود
- النتائج النهائية: **138/138 اختبار خادم، 184/184 اختبار تطبيق**؛ lint وTypeScript و`git diff --check` ناجحة.
- أعيد تشغيل `Masarak preview`: HTTPS health يعيد 200 و`configured:true`، وطلب التحليل غير الموثق يعيد 401 قبل معالجة الملف. فحصت شاشة الرفع بصريًا بعرض 402px؛ النتائج والمراجعة/الحفظ تحققت بالاختبارات، لا بجلسة مستخدم حي أو هاتف.
- اختبارات تركيبية/محاكاة مخصصة للمخطط الصارم والنموذج الافتراضي والتجاوز الصريح، وفشل المفتاح/النموذج، وسجلين لكل تعليم/مشاريع/خبرات، ومنع استعارة الجامعة/الجهة بين السجلات، والأدلة والصفحات، وPDF حقيقي مولّد في الذاكرة.
- اختبارات القواعد المحلية القديمة تُحقن فيها الدالة المحلية صراحةً؛ لا تعني وجود fallback في تشغيل التطبيق. اختبارات المزوّد الجديدة تختبر المسار الفعلي بمحاكاة HTTP، والتجربة التشغيلية أعلاه منفصلة عنها.
- هذا لا يثبت دقة عامة لكل PDF أو تجربة هاتف حقيقي أو حفظًا سحابيًا حيًا. لم تُستخدم السيرة الأصلية. غموض الأعمدة والحقول غير المذكورة يظل بحاجة لمراجعة.
- استدعاء استكمال التغطية الموجود مسبقًا قد يضيف طلبًا واحدًا للمشاريع/الأنشطة الناقصة. التجربة التشغيلية الحالية قيّدته بطلب واحد ولم تحتج استكمالًا.
