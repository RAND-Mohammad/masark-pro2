# مسارك — قائمة متابعة التقرير ومعايير القبول

> تحديث Phase 1 الحالي وحدود الاختبار والاعتماد الخارجي في [تقرير Phase 2](PHASE-2-STATUS_AR.md). البنود القديمة أدناه سجل متابعة سابق؛ لا تُعد جميعها وصفًا للحالة الحالية ولا دليلًا على قبول حي.

آخر تحديث: 2026-10-15.

## طريقة العمل

- الهدف تطبيق iOS وAndroid؛ معاينة الويب أو نجاح اختبارات المحاكاة لا يثبتان نجاح نسخة الجوال.
- ننفذ مهمة واحدة محددة في كل مرة، نوثق دليلها ونختبرها ونثبت النسخة ثم نتوقف لعرض النتيجة؛ لا نبدأ المهمة التالية ضمنها.
- التقرير الأصلي مرجع للنطاق وليس وصفًا مؤكّدًا للحالة الحالية. المراحل التالية لم يُعَد تدقيق تنفيذها ضمن فحص المرحلة الأولى.
- `[x]` دليل متوفر، `[ ]` لم يتحقق معيار القبول بعد. لا تعني الخانة المفتوحة بالضرورة أن الكود غير موجود.
- لا نشر عام أو حذف بيانات أو تعديل صلاحيات خارجية ضمن هذا الفحص.
- التفاصيل والأدلة وحدود المرحلة الأولى: [سجل التحقق](PHASE-1-VERIFICATION_AR.md).

## 1. الحسابات والبريد والمزامنة وعزل البيانات

**الحالة: المراجعة والإصلاحات المحلية مكتملة؛ القبول الحي والجوال لا يزالان مفتوحين.**

- [x] مراجعة التسجيل والدخول واستعادة الجلسة والخروج؛ توجد اختبارات فعلية للكود باستخدام مزوّد محاكى.
- [x] التسجيل يؤكد البريد برمز من 6 أرقام؛ الدخول المعتاد بكلمة مرور.
- [x] لا يُعامل رد الدخول أو تأكيد الرمز الخالي من جلسة على أنه نجاح.
- [x] انتقال شاشة الاستعادة مع وصول جلسة فعلية، وفصل رابط الاستعادة عن خيار الرمز الاحتياطي.
- [x] رفض عرض نجاح تغيير كلمة المرور دون مستخدم مطابق للحساب، ومنع النقرات المتزامنة وإعادة الإرسال المبكر محليًا.
- [x] تنظيف بيانات روابط التأكيد من عنوان المتصفح حتى عند فشل الرابط.
- [x] مراجعة التخزين حسب مالك البيانات، والموافقة على المزامنة، وتعارض الأجهزة والإصدارات، وربط الطلب بجلسة صاحبه.
- [x] طلب حي بلا تسجيل دخول إلى جدول الحسابات مرفوض بـ HTTP 401 / PostgreSQL 42501.
- [x] إعداد Supabase الحي يتيح البريد وكلمة المرور ويطلب تأكيد البريد.
- [x] أكد المستخدم من فحص SQL في اللوحة سياسات العمليات الأربع بشرط `auth.uid()=user_id` وصلاحيات authenticated الأربع true وanon الأربع false.
- [ ] استكمال ما لم تُرفق نتيجته من فحص القراءة فقط: تفعيل RLS فعليًا، وRPC ومخزن السير الخاص، وعدم وجود سياسة إضافية تمنح وصولًا عامًا.
- [ ] اختبار حسابين تجريبيين مصرح بهما: A لا يقرأ أو يعدل أو يرفع أو يستبدل بيانات/ملفات B حتى عند تغيير المعرف والمسار؛ الضيف مرفوض أيضًا.
- [ ] تحقق حي للمالك: حفظ واسترجاع ملف الحساب والمهارات والخطة والتقدم والشهادات والسيرة؛ نقل الجلسة إلى جهاز ثانٍ دون فقد.
- [ ] تعديل دون اتصال ثم مزامنة، وتعارض جهازين مع اختيار صريح، وتبديل الحساب/الخروج أثناء طلب جارٍ دون تسرب بيانات.
- [x] أكد المستخدم تفعيل Send Email Hook من اللوحة وظهور Enabled؛ لم يفعله الوكيل.
- [ ] مطابقة روابط العودة على بناء الجوال الفعلي دون تغييرها أو توسيعها افتراضيًا.
- [ ] تسجيل حقيقي بعد التفعيل: رمز خاطئ/صحيح/منتهي، إعادة إرسال، بريد غير مؤكد، خروج ودخول، واستعادة رابط لمرة واحدة ثم دخول بكلمة المرور الجديدة.
- [ ] إعادة الفحص على بناء تطوير iOS وعلى Android، وليس Expo Go/معاينة الويب فقط.

**بوابة الإغلاق:** إرفاق نتائج SQL وفحص الحسابين والجهازين والبريد الحقيقي والجوال؛ لا تكفي الاختبارات المحلية لإغلاق المرحلة.

## 2. حماية خادم التحليل والخصوصية

**الحالة: أُنجز إصلاح مصادقة خادم التحليل محليًا باختبارات محاكاة؛ بقية متطلبات المرحلة والتحقق الحي مفتوحة.**

- [x] تنفيذ تحقق خادم التحليل من access token لدى Supabase قبل استقبال الملف ومعالجته؛ اختبارات محاكاة للرفض والقبول، دون الاعتماد على CORS أو user_id من العميل. [الدليل والحدود](CV-SESSION-VERIFICATION_AR.md).
- [ ] التحقق الحي من حماية مسار التحليل بجلسة حقيقية بعد تجهيز تشغيل الخدمة بأمان؛ الاختبارات المحلية لا تعني تفعيلًا خارجيًا.
- [ ] Groq وأي مفاتيح إدارية في الخادم فقط؛ لا service-role في التطبيق أو مستودع الملفات أو السجلات.
- [ ] اتصالات HTTPS وعنوان خادم صالح للجوال، دون ربط التطبيق بعنوان localhost.
- [ ] فحص نوع/حجم/محتوى الملف وحدود الطلبات والمهلة والمعالجة المعزولة، ورسائل فشل واضحة.
- [ ] موافقة صريحة قبل نقل السيرة لمزود خارجي، مع بيان البيانات والمزود والغرض.
- [ ] سياسة خصوصية واحتفاظ وحذف قابلة للتنفيذ، وحذف الحساب وبياناته وملفاته باختبار آمن وموافقة منفصلة قبل أي حذف حي.
- [ ] التعامل مع نص السيرة ومخرجات النموذج كمدخلات غير موثوقة، واختبار التعليمات الخبيثة والملفات التالفة وعدم تسجيل محتواها.

**بوابة الإغلاق:** المستخدم غير المصرح مرفوض، والحدود والخصوصية مطبّقة فعليًا بخادم وواجهة واختبارات.

## 3. استخراج السيرة وتحليلها

- [ ] تجربة PDF وDOCX نصيين وعربيين وإنجليزيين، مع إظهار حدود الاستخراج.
- [ ] حسم نطاق OCR للصور/PDF الممسوح بوضوح؛ لا ادعاء دعمه قبل تنفيذه واختباره.
- [ ] استدعاء Groq عبر الخادم بعد الموافقة، ومعالجة الانقطاع والحصص دون اختلاق تحليل.
- [ ] نتائج منظمة قابلة للتحقق والتصحيح، تتعامل مع المهارات والأدلة والمعلومات الناقصة دون تأكيدات غير مسندة.
- [ ] مجموعة ملفات تقييم مجهولة الهوية بموافقة أصحابها، ومراجعة بشرية ومقاييس استخراج/تحليل موثقة.

**بوابة الإغلاق:** تحليل من ملف حقيقي إلى واجهة وحفظ مملوك للمستخدم، مع أمثلة ناجحة وحالات فشل موثقة.

## 4. المسارات وتغطية المهارات وخطة التعلم

- [ ] مراجعة المسارات الستة المذكورة في التقرير ومصادر متطلباتها وتاريخ مراجعتها.
- [ ] تمييز تغطية المهارات عن الجاهزية الوظيفية؛ أي تقدير جاهزية يوضح الأدلة والوزن والحدود ولا يضمن التوظيف.
- [ ] ربط الفجوات بخطة عملية ومصادر تعلم موثوقة ومحدّثة؛ لا روابط أو دورات مختلقة.
- [ ] إنشاء/تعديل الخطة وتحديث الإنجاز والتراجع عنه، وحفظ واستعادة التقدم والشهادات ومزامنتها.
- [ ] اختبار اختلاف الملفات والخبرات والمدخلات الناقصة وعدم تضخم الدرجات أو احتساب المهارة مرتين.

**بوابة الإغلاق:** رحلة ملف ← فجوة موضحة ← تعلم ← تقدم محفوظ وقابل للاستعادة، مع حسابات قابلة لإعادة التحقق.

## 5. وظائف حقيقية وربط المهارات

- [ ] اختيار مصدر مصرح باستخدامه والتحقق من شروطه والحصص، دون اختلاق وظائف أو جمع غير مسموح.
- [ ] مصدر ورابط أصلي ومعرف وتاريخ جلب لكل فرصة، وآلية تحديث دورية ومراقبة فشل التحديث.
- [ ] إزالة التكرار والتعامل مع انتهاء الوظائف والبيانات الناقصة، مع بحث وتصفية مفيدين.
- [ ] ربط المتطلبات بمهارات المستخدم وشرح سبب المطابقة والفجوات، دون تقديم درجة المطابقة كضمان قبول.
- [ ] اختبار الاستيراد والعرض والتحديث والفشل والقدم بمصدر حقيقي معتمد.

**بوابة الإغلاق:** يمكن فتح وظيفة حقيقية في مصدرها وتتبع مصدرها وحداثتها وسبب مطابقتها.

## 6. اتجاهات السوق ولوحة المؤشرات

- [ ] تعريف المؤشرات والبلد/الفترة ووحدة القياس قبل بناء الرسوم.
- [ ] عرض المصدر وتاريخ التحديث وحجم العينة وحدود التغطية والتحيز؛ لا تعميم العينة على السوق كله.
- [ ] احتساب يمكن إعادة إنتاجه من البيانات المسموح بها، وتجنب التكرار والمقارنة بين فترات غير متكافئة.
- [ ] حالات فارغ/تحميل/خطأ/بيانات قديمة، واختبار صحة الأرقام والفلاتر وإتاحة العرض.

**بوابة الإغلاق:** كل رقم قابل للتتبع والحساب، ولا توجد نتائج أو اتجاهات مخترعة.

## 7. محاكاة المقابلات والتقييم

- [ ] أسئلة مرتبطة بالمسار/الوظيفة ومستوى الخبرة، وحوار قابل للإكمال والاستئناف.
- [ ] معايير تقييم معلنة وملاحظات مرتبطة بالإجابة وأمثلة تحسين، لا أحكام توظيف قطعية.
- [ ] عدم الثقة بتعليمات المستخدم داخل الإجابة وعدم كشف أسرار أو إجابات مستخدمين آخرين.
- [ ] حفظ مملوك للمستخدم وسياسة احتفاظ، مع اختبار إجابات صحيحة/ضعيفة/فارغة/خبيثة.
- [ ] تقييم بشري منظم للملاءمة والاتساق والتحيز قبل اعتبار التقييم موثوقًا.

**بوابة الإغلاق:** مقابلة كاملة محفوظة وتقييم مفسّر ومتسق ضمن حدود معلنة.

## 8. لوحة الإدارة وصلاحياتها

- [ ] تعريف ما يديره المشرف، وربط الأدوار بمصدر موثوق في الخادم لا بحقل يستطيع المستخدم تغييره.
- [ ] حماية كل واجهة وطلب، لا إخفاء زر فقط؛ اختبار مستخدم/ضيف/مشرف ورفض تجاوز المعرف.
- [ ] إدارة المصادر/المحتوى المطلوبة دون توسيع الوصول إلى السير والبيانات الشخصية بلا حاجة.
- [ ] سجل تدقيق آمن، وتأكيد العمليات الحساسة وإمكانية المراجعة، واختبار إنشاء/تعديل/حذف بمعلومات تجريبية فقط.

**بوابة الإغلاق:** صلاحيات مثبتة بالاختبارات، وعمليات الإدارة المطلوبة تعمل من الواجهة إلى الخادم.

## 9. التقييم الشامل والاستعداد لنشر الجوال

- [ ] مصفوفة تربط متطلبات التقرير بحالات اختبار ونتائج فعلية ومشكلات متبقية.
- [ ] قياس جودة التحليل والمطابقة والمقابلات بعينات معلومة وحدود معلنة، لا أرقام افتراضية.
- [ ] اختبار رحلة كاملة على iOS وAndroid: حساب وسيرة ومسار وخطة ووظائف ومؤشرات ومقابلة ومزامنة.
- [ ] اختبارات العربية/RTL وإتاحة الوصول والشاشات الصغيرة والأداء والشبكة الضعيفة والاستئناف.
- [ ] مراجعة أمن واعتماديات وخصوصية، وخطة نسخ احتياطي/استعادة ومراقبة أخطاء دون بيانات حساسة.
- [ ] إعدادات builds والروابط العميقة والتوقيع وسياسات المتاجر وبيانات الخصوصية ولقطات العرض جاهزة.
- [ ] موافقة المالك على الإطلاق بعد إغلاق العيوب المانعة؛ لا نشر تلقائي.

**بوابة الإغلاق:** أدلة قبول كل مرحلة وبناءان مجربان وخطة تشغيل وموافقة صريحة. المشروع ليس جاهزًا للنشر بمجرد مرور الاختبارات المحلية.
