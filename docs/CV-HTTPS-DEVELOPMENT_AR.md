# تشغيل خدمة تحليل السيرة عبر HTTPS في التطوير

## التغيير المحدد

- بقي عنوان Expo العام في `EXPO_PACKAGER_PROXY_URL` ضمن أمر تشغيل workflow نفسه.
- يشغّل `scripts/start-dev.mjs` خدمة التحليل على Unix socket خاص بصلاحية 0600 دون منفذ TCP، ثم Expo على 5000، ويوقف العمليتين معًا عند الإيقاف أو فشل إحداهما.
- يضبط المشغّل `EXPO_PUBLIC_CV_API_URL` في بيئة عملية Expo إلى أصل HTTPS الحالي مضافًا إليه `/api/cv`، دون تثبيت اسم نطاق في الكود أو تعديل Secrets.
- الويب يستخدم مسارًا نسبيًا من الأصل نفسه، وAndroid وiOS يستخدمان العنوان المطلق عبر HTTPS.
- يمرّر Metro فقط `/api/cv/health` و`/api/cv/analyze-cv` إلى الخدمة الداخلية. لا يمرّر مسار البريد أو عناوين اختيارية من الطلب.
- لم تُوسّع CORS أو صلاحيات Supabase. في المحاولة الأولى أضافت المنصة تلقائيًا خيار كشف منفذ loopback؛ أُوقف التشغيل واستُبدل TCP باتصال Unix خاص. ولأن المنصة أعادت الخيار على خريطة المنفذ القديم، أُزيل ربط 3001 غير المستخدم كله باستبدال إعداد متحقق منه. لا يوجد منفذ خارجي جديد؛ منفذ Expo العام السابق بقي كما هو.
- المصادقة السابقة لدى Supabase تبقى قبل Multer واستخراج النص وGroq، وترويسة Bearer تُمرّر دون استبدالها بهوية أخرى.
- إصلاح الأيقونات وإعدادات splash وروابط المصادقة لم تتغير.

## أدلة محلية

نجحت 30 حالة للعميل والمصادقة ووسيط التطوير باستخدام محاكاة للمزوّدين واتصالات محلية فقط، ومنها اتصال Unix الفعلي.
نجح lint وفحص TypeScript وصياغة مشغّل التطوير.

```sh
node --test tests/cv-dev-proxy.test.cjs tests/cv-api.test.cjs server/cv-session.test.mjs
npm run lint
npx --no-install tsc --noEmit
node scripts/check-cv-https.mjs
```

## نتائج HTTPS الفعلية

| الفحص | النتيجة |
|---|---|
| `/api/cv/health` | HTTP 200، حالة ok |
| `/api/cv/analyze-cv` بلا توكن، مع multipart غير صالح بلا ملف أو موافقة | HTTP 401 قبل وصوله إلى محلّل الملفات |
| `/api/cv/api/auth/send-email` | HTTP 404؛ لا يمرّر وسيط التطوير مسار البريد |
| `/favicon.ico` | HTTP 200 |
| اتصال خدمة CV الداخلي | Unix socket خاص، دون أي استماع TCP على 3001، مثبت من قوائم النظام |
| Manifest Android وiOS | HTTP 200 لكل منهما |
| روابط فتح Expo المولّدة | HTTP 200، المضيف العام والمنفذ الافتراضي صحيحان |
| ملفات JavaScript من launchAsset الأصلي دون تصحيح الرابط | HTTP 200 لكل منصة |
| عنوان API في حزمتَي المنصتين | عنوان HTTPS الحالي مع `/api/cv` موجود في كلتيهما |
| معاينة الويب | الصفحة العامة ظهرت دون انهيار |

النتيجة التفصيلية محفوظة محليًا في `generated-artifacts/cv-https/verification.json`؛ هذا مجلد مستبعد من Git والنشر.
لم تُحفظ ملفات حزم المنصتين الكبيرة على القرص.

## المانع وحدود الاختبار

- فحص وجود `GROQ_API_KEY` أعاد false، وأكدت صحة الخدمة أنه غير مضبوط في العملية المشغّلة. لم نقرأ قيمته أو نضف مفتاحًا.
- عند غياب المفتاح، يقدم الخادم تحليلًا أساسيًا محليًا ضمن العملية للمهارات الحرفية والخبرات الواضحة تحت أقسامها، بأدلة من النص ودون تخمين بيانات ناقصة. يعيد بقية الأقسام فارغة وتحذيرًا واضحًا؛ لا يرسل النص إلى Groq.
- التحليل الأشمل عبر Groq ما زال يتطلب مفتاحًا مضبوطًا للخادم وموافقة المستخدم قبل البدء. لم نجرّب هذا المسار أو نرسل سيرة المستخدم.
- لم نقرأ أو نرسل سيرة المستخدم المرفوعة من الواجهة، ولم نضغط موافقته أو نستدعِ Groq.
- لم نستخدم جلسة مستخدم فعلية لإرسال ملف؛ نجاح الجلسة والرفض التفصيلي اختُبرا بالمحاكاة، والرفض بلا جلسة اختُبر عبر HTTPS الفعلي.
- لم يُنفذ اختبار هاتف أو build أو نشر إنتاجي أو اتصال بـGitHub. نجاح تنزيل الحزم لا يُغلق اختبار الهاتف المعلّق.
- لا يزال الخادم نموذجًا تطويريًا؛ هذا الربط لا يثبت اكتمال جميع متطلبات حماية الملفات والخصوصية أو جاهزية النشر.
