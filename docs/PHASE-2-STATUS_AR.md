# حالة Phase 1 ومتطلبات التحقق وPhase 2

> هذا سجل تحديثات سابق. الحالة الحالية ومزود تحليل السيرة الحالي موضحان في `PHASE2_STATUS.md`؛ لا تعتبر إشارات Groq القديمة أدناه دليلًا على اختبار التغيير الأخير.

## استكمال تصدير سيرة الطالب — 2026-10-20
المعاينة تنشئ وتشارك PDF محليًا على iOS/Android باستخدام وحدتي Expo الرسميتين، مع بقاء طباعة الويب. اختبارات العميل **181/181** والخادم **116/116** وlint وTypeScript ناجحة؛ لا تجربة محاكي نظام أو هاتف فعلي أو مزامنة حية جديدة. الإغلاق الكامل للمسار لا يزال معلقًا على قبول الأجهزة والحسابات. الحالة المختصرة الحالية في [PHASE2_STATUS.md](../PHASE2_STATUS.md)؛ الفقرات التالية سجل للتحديثات السابقة وليست نفيًا لوجود التصدير الأصلي الآن.

## تحديث محدد — مسار الطالب بلا سيرة (2026-10-20)
أُضيفت بداية بخياري PDF إنجليزي اختياري أو إجابات قصيرة، ومسار تعليم/مهارات/مشاريع/دورات/اهتمامات بخبرة اختيارية ومراجعة قبل الحفظ. يستخدم نفس نموذج الملف والحسابات الحالية دون حذف البيانات السابقة أو تغيير Supabase. المعاينة المحفوظة قابلة للطباعة أو الحفظ PDF من الويب؛ لا تصدير أصلي للجوال. التفاصيل والحدود ودليل الاختبارات في [تقرير مسار الطالب](STUDENT-PROFILE_AR.md). نتائج الفحوص بعد هذه الإضافة: **173 عميل و116 خادم**، وlint وTypeScript ناجحة. ما يلي يظل وصفًا للتحديث السابق، ولا يُعتبر إثباتًا جديدًا للحفظ الحي أو الهواتف.

## حدود هذا التحديث
استُكمل التنفيذ داخل Expo/React Native وSupabase الموجودين، دون إعادة بناء أو ترقية حزم أو نشر أو تغيير إعدادات المشاركة والصلاحيات. لم تُنشأ قاعدة بديلة ولم تُنقل قاعدة الزميلة. لا توجد مفاتيح داخل تطبيق العميل؛ مفاتيح مزود AI تبقى في بيئة الخادم.

## الخلفية وقاعدة البيانات الفعلية
- الواجهة تستخدم Supabase Auth/Data API/Storage الحقيقيين. PostgreSQL الحالية تحتوي جدول `masarak_account_data` المرتبط بمستخدم الحساب، ونسخة JSONB مع revision لقفل التعديلات المتعارضة. ملفات PDF في `masarak-cvs` الخاص. هذه ليست قاعدة في الذاكرة أو backend تجريبيًا.
- نتائج المقابلات أُضيفت إلى نسخة الحساب نفسها، مع عزل التخزين المحلي وتتبع التغييرات والمزامنة واسترجاعها على جهاز آخر. لم يلزم تغيير RLS أو إنشاء جداول بصلاحيات جديدة. السجلات القديمة التي لا تحتوي مقابلات تظل مقبولة.
- التخزين المحلي ليس بديلًا سريًا للسحابة: تفعيل الحفظ السحابي اختياري، والواجهة تميز المحلي والمعلق والمتزامن والتعارض والفشل. لا ينبغي اعتبار وجود الإعدادات وحده إثباتًا لحفظ حي.
- Express يقدم `/analyze-cv` و`/interview/questions` و`/interview/evaluate`. جميع مسارات المقابلة تحتاج جلسة تتحقق منها Supabase، وبحدود للطلب والتكرار. في التطوير يصل العميل إليها من جسر HTTPS الحالي `/api/cv` عبر Unix socket خاص؛ لم يُفتح منفذ خادم إضافي.
- التوصية والفجوات والجاهزية حسابات شفافة في العميل من البيانات المحفوظة، وليست تنبؤات AI من الخادم. لا توجد خدمة سوق وظائف أو نفاذ.

## إعدادات البيئة
- الموجود بالفعل: `EXPO_PUBLIC_SUPABASE_URL` و`EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY`. المفتاح publishable عام بطبيعته؛ لا يوضع service-role في التطبيق.
- مشغل التطوير يمرر `EXPO_PACKAGER_PROXY_URL` و`EXPO_PUBLIC_CV_API_URL` للعنوان HTTPS الحالي. يجب إعداد عنوان API صالح مستقل قبل إصدار إنتاجي؛ جسر Metro ليس إعداد استضافة إنتاج.
- اختياري للخادم فقط: `GROQ_API_KEY` و`GROQ_MODEL`؛ لا حاجة للمفتاح لتشغيل البديل المحلي. المقابلة لا ترسل إجابة خارجيًا إلا عند اختيار AI والموافقة المنفصلة. فشل مزود مهيأ يرجع خطأ واضحًا، لا نتيجة AI مختلقة.
- البريد يعتمد على Edge Function الموجودة وBrevo وأسرارها في Supabase، وليس مجرد وجود الأسرار في Replit.

## دليل الاختبار وحدوده
- فحص قراءة حي لـSupabase Auth أعاد أنه متاح، وتسجيل البريد وإنشاء الحسابات مفعلان، وتأكيد البريد مطلوب. لم يُنشأ مستخدم أو تُرسل رسالة أثناء الفحص.
- اختبارات PDF العربية والإنجليزية تحافظ على مسار الرفع الحقيقي والاستخراج والمراجعة.
- اختبارات المقابلة تغطي HTTP فعليًا على loopback، غياب الجلسة، الحد والتكرار والموافقة، التقييم المحلي واللغتين، مزود AI بمحاكاة فقط، وعدم إرسال إجابة تحت حساب تغيّر أثناء طلب الجلسة.
- اختبار الحفظ يشغّل كود العميل والتخزين والمزامنة الفعلي مع **محوّل Supabase محاكى** ثم استرجاع من جهاز محاكى آخر. لا يثبت كتابة في قاعدة المستخدم الحية. اختبارات الشاشة تشغّل المعالجات بمحاكاة React Native؛ ليست تجربة هاتف فعلي.
- الأوامر: `npm --prefix server test`، `node --test tests/*.test.cjs tests/*.test.mjs`، `npm run lint -- --no-cache`، `npx --no-install tsc --noEmit`.

## ما لم يُفعّل أو يُثبت بعد
1. **قبول الحفظ السحابي الحي:** يلزم اختبار بحسابين مصرحين وجهازين: تمكين المزامنة، حفظ الملف وPDF والنتائج، استرجاعها، تغيير الحساب، التعارض وعدم تسرب البيانات. فحص RLS/صلاحيات الجدول وStorage وRPC قراءةً من لوحة Supabase. الكود متصل، لكن لم أستخدم جلسة المستخدم أو service-role لإثبات ذلك.
2. **البريد:** لم تُرسل رسائل ولم تتغير إعدادات Hook. تأكيد المستخدم السابق لتفعيله لا يغني عن اختبار إنشاء حساب/استعادة على الأجهزة قبل الإطلاق. التحقق من أسرار Edge والبريد والروابط الخارجية يحتاج اللوحة.
3. **الهواتف والإصدار:** تجربة Expo Go الفعلية السابقة مؤجلة؛ لم تُعتبر ناجحة. يلزم اختبار Android/iOS وروابط العودة ورفع PDF والتخزين. معرّفات الحزم وإعداد بناء/توقيع إصدار نهائي تحتاج اعتمادًا لاحقًا، دون بدء build أو نشر الآن.
4. **AI/NLP:** المفتاح غير مهيأ حاليًا. المسار مبرمج واختُبر بالمحاكاة، ولم يُرسل CV أو جواب فعلي لأي مزود. المحلل المحلي قد يفوّت تنسيقات حرة أو أعمدة ملتبسة؛ لا يعيد ترتيب التواريخ ليخمن حقائق. يلزم تقييم دقة منظم على بيانات مصرح بها قبل إطلاق ادعاءات جودة.
5. **الخصوصية وحذف الحساب:** أُضيفت صفحة توضيح التنفيذ، لا سياسة قانونية نهائية. يلزم اعتماد المسؤول وسياسة الاحتفاظ وموقع المعالجة ومسار حذف الحساب وجميع نسخه بصلاحيات خادم آمنة. لا يوجد زر حذف حساب وهمي أو مفتاح إدارة داخل التطبيق.
6. **اللغات:** تدريب المقابلة وبطاقة حفظه يدعمان العربية/الإنجليزية واتجاهيهما. السير والنصوص الإنجليزية محفوظة. بقية الواجهات تبقى عربية أساسًا كما كانت؛ ترجمة واجهة التطبيق كاملة للإنجليزية لم تُنجز ضمن هذا التحديث.
7. **المصادر:** الكتالوج مرجعي ثابت، وروابط الدورات ليست تحقق إكمال من المزود. وظائف/تدريب حي وتحديث دوري يتطلبان مصدرًا مصرحًا وتكامله؛ لم يُختلق مصدر أو أرقام سوق.
8. **ترقية عملاء متعددي الإصدارات:** بيانات المقابلة حقل جديد في النسخة. يجب تحديث الأجهزة المستخدمة قبل الاختبار؛ العملاء الأقدم الذين لا يحفظون الحقل قد يستبدلون نسخة JSON دون الاحتفاظ به. فصل الكيانات في جداول أو تقوية عقد الإصدار قرار Phase 2 يحتاج مراجعة schema وصلاحيات مصرحًا بها.
