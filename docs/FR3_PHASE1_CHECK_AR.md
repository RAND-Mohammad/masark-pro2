# FR3 — فحص وإكمال مسار السيرة في Phase 1

تاريخ التحقق: 2026-10-21. هذا تحقق محلي، وليس إعلان جاهزية إنتاج أو إثبات دقة عامة.

**تحديث 2026-10-23:** أعيد ربط تحليل PDF بـGroq، النموذج الافتراضي `openai/gpt-oss-120b`، مع إرسال نص PDF المستخرج فقط والتحقق من الأدلة محليًا. التعديل محلي ولم يُختبر باتصال حي بعد هذا التحويل. سجل Groq بتاريخ 2026-10-21 في أسفل هذا الملف يخص تجربة سابقة ولا يُعد قبولًا للربط الحالي. راجع `GROQ_CV_ANALYSIS_AR.md`. كذلك يحدد بند 3.7.1 في التقرير Python، بينما الباك إند المنفذ Node.js/Express بقرار الفريق السابق؛ يجب تسجيل هذا الاختلاف في تقرير Phase 2.

## النطاق المحفوظ
- Expo/React Native وNode.js/Express وSupabase كما هي؛ لم يحدث تحويل إلى Python. التقرير يذكر Python في بند 3.7.1، لذا هذا اختلاف تقني يجب تحديثه في تقرير Phase 2، وليس ميزة جديدة.
- PDF نصي إنجليزي فقط، حتى 10MB، دون صور أو Word أو OCR. بقي تنبيه «يرجى رفع السيرة الذاتية بصيغة PDF فقط» وحماية الجلسة قبل معالجة الملف.
- المسار الموجود: رفع ← استخراج النص ← تحليل منظم ← مراجعة وتصحيح واستبعاد ← اعتماد وحفظ ← استخدام المهارات المعتمدة في المستهلكين الحاليين.
- ستة أقسام مستقلة: المهارات والمشاريع والدورات والشهادات والتعليم والخبرات. الأنشطة والبنود غير المصنفة محفوظة للمراجعة؛ غير المصنف ليس مؤهلًا معتمدًا.

## ما تغير
- يفحص الخادم رد المزوّد بنيويًا أيضًا، ولا يكتفي بطلب JSON Schema: الأقسام والحقول التفصيلية مطلوبة، والأنواع والحدود والخصائص الزائدة تتحقق قبل القبول.
- يتحقق من اقتباس البند ضمن قسمه، ومن كل قيمة ضمن اقتباس البند نفسه. تُحذف القيم غير المسندة وتُعلّم الحقول غير المؤكدة للمراجعة بدل استعارة جهة أو تخصص من قسم آخر.
- تبقى المشاريع/الأنشطة المذكورة صراحةً تحت قسم الخبرة قابلة للتصنيف في أقسامها الصحيحة، دون تحويلها إلى وظيفة أو اختراع صاحب عمل. صف PDF متعدد الأعمدة يوقف الربط غير الموثوق.
- تُنشأ أدلة الحقول من النص الفعلي في الخادم؛ لا تُقبل تصريحات المزوّد عن المصدر كدليل بحد ذاتها. تبقى مصادر التصحيحات اليدوية الأصلية محفوظة.
- وصف مثل «Designed an optimized Priority Scheduling Algorithm using Priority Queue» يبقى وصفًا ويترك اسم المشروع فارغًا يحتاج مراجعة إذا لم يوجد عنوان مستقل.
- تُستكمل المهارات الحرفية التي قد يسقطها المزوّد من الاستخراج المحلي المحافظ، مع إزالة التكرار وإعادة التحقق من الربط بالقاموس؛ لا تُستنتج مهارات من اسم الجامعة أو الوظيفة.
- يتحدث وسم حالة القسم إذا استعاد فحص التغطية نتيجة مفقودة. تغير إصدار المحلل، ولذلك تستخدم النتائج القديمة مسار إعادة التحليل والمراجعة الموجود، دون اعتماد تلقائي.
- حذف PDF يحذف الحقائق والمهارات المشتقة منه، ولا يحوّلها إلى اختيارات يدوية. تبقى الاختيارات اليدوية والحقائق المضافة يدويًا بشكل مستقل، ومنها بيانات الملف السابق المنشأ من الإجابات.
- تؤكد الاختبارات أن المسودة لا تؤثر على التوصيات/الفجوات قبل الاعتماد، وأن استبدال الاعتماد أو حذفه يزيل مساهمة السيرة القديمة ويحافظ على البيانات اليدوية.

## ما لم يُثبت وما يحتاج تهيئة
- كان `GROQ_API_KEY` غير محفوظ عند فحص الوحدة السابق. أضافه المستخدم لاحقًا وأذن بفحص تشغيلي تركيبي محدود؛ انظر النتيجة أدناه. لم ترسل أي سيرة حقيقية. التحليل المحلي عند غياب المفتاح بديل محدود بالقواعد، وليس AI كاملًا.
- الإرسال من الواجهة يتطلب تسجيل الدخول وموافقة المستخدم الموجودة قبل الإرسال. الاختبار التشغيلي التالي لا يثبت تجربة HTTP موثقة بحساب حي.
- لم تُختبر أجهزة iPhone/Android فعلية أو مزامنة حية بحسابين. اختبارات التخزين الحالية محلية/محاكاة، ولا تثبت الكتابة أو العزل في Supabase الحي.
- لم تُستخدم أو تُختبر سيرة شخصية في هذه المهمة. الاختبارات تركيبية ولا تعني نجاح كل تنسيق PDF.
- لا يمكن استعادة مصدر بيانات قديمة فقدت تمييز اليدوي عن المستخرج سابقًا بصورة موثوقة؛ تحتاج مراجعة المستخدم، ولا يعاد تصنيفها تخمينًا.
- لم تتغير المصادقة أو Supabase/RLS أو مخططات قاعدة البيانات أو وحدات التوصيات والمقابلات، ولم يحدث نشر.

## فحص Groq الحقيقي المحدود — 2026-10-21
- تحقق وجود المفتاح فقط عبر واجهة Secrets دون كشفه. أعيد تشغيل `Masarak preview`، وأصبح فحص HTTPS للخدمة يعيد `{"status":"ok","configured":true}`. بقي الطلب غير الموثق للتحليل مرفوضًا بـ401.
- طلب خارجي واحد فقط: PDF إنجليزي تركيبي مولّد في الذاكرة ← استخراج PDF الحقيقي ← `analyzeText` الحقيقي ← Groq. لم يُتجاوز HTTP المحمي ولم تُنشأ حسابات، ولم تستخدم سير أو بيانات مستخدمين.
- استجابة Groq: **HTTP 200**، النموذج المطلوب والمُعاد `openai/gpt-oss-20b`، و`finish_reason: stop`. التقط الاختبار اسم النموذج ومعرف completion من الاستجابة الحقيقية؛ لم يكن fallback محليًا. النتيجة المخزنة الحالية لا تحتوي حقل provider/model مستقلًا.
- أعداد النتائج: **3 مهارات، 1 تعليم، 1 مشروع، 1 خبرة، 1 دورة، 1 شهادة**. كل بند يحمل دليلًا، وكل قسم يحتوي أدلة حقول، واجتازت الاستجابة التحقق البنيوي الفعلي.
- **القبول التشغيلي جزئي وليس كاملًا:** الاتصال والمخطط نجحا، لكن اسم الجامعة بقي فارغًا وبحاجة للمراجعة؛ لذلك فشل شرط اكتمال بيانات التعليم في فحص العينة. لم يُخفف التحقق ولم يُخمن الاسم ولم تتكرر الطلبات. لا يكفي وجود قسم التعليم لإثبات اكتمال حقوله.
- لم يعدّل كود التكامل أو النموذج أو المفتاح. lint وTypeScript ناجحان؛ لم تُعد كامل اختبارات المشروع دون تغيير كود.
- يمكن بدء تجربة PDF إنجليزي وهمي من الواجهة بعد تسجيل الدخول وموافقة الإرسال، مع مراجعة النتائج. يلزم تحقق منفصل/إصلاح محدود لحالة الجامعة قبل ادعاء نجاح العينة بالكامل، وما زال تحقق الهواتف والحفظ السحابي الحي غير مثبت.
