# Send Email Hook لمسارك

> هذا مسار Node السابق، وليس المسار المعتمد الآن. اختار الفريق تشغيل الدالة داخل Supabase دون نشر مسارك أو خادم Replit. اتبعوا [إعداد دالة Supabase](SUPABASE-EMAIL-HOOK_AR.md) بدل خطوات النشر الواردة أدناه.

## ما الذي تغيّر؟

التحقق من التسجيل الجديد برمز من 6 أرقام يبقى لدى Supabase. الخادم يستقبل طلب Supabase الموقّع ويرسل رسالته عبر ربط Brevo الآمن في Replit، بدون نسخ مفتاح Brevo إلى التطبيق أو إلى Supabase. رسائل استعادة كلمة المرور تبقى روابط متوافقة مع شاشة الاستعادة الموجودة.

دعمنا أيضًا الدعوات وروابط الدخول وتأكيد تغيير البريد وإعادة التحقق. أنواع الرسائل غير المدعومة تفشل صراحةً بدل ادعاء إرسالها. لا تفعلوا أنواع إشعارات جديدة قبل إضافة دعمها واختبارها.

هذا خادم Node في Replit، وليس دالة Postgres أو Supabase Edge Function. ربط Brevo المستخدم يتطلب بيئة Replit. اختروا **HTTPS** في إعداد Send Email Hook، وليس Postgres.

## المتطلبات

- اتصال Brevo مضاف للمشروع، مع مرسل مفعّل وخدمة إرسال متاحة.
- نشر خادم رسائل التحقق بعنوان HTTPS ثابت وعام يمكن لـSupabase الوصول إليه. المعاينة `.replit.dev` ليست عنوانًا لتفعيل الـHook.
- SEND_EMAIL_HOOK_SECRET: مفتاح التوقيع الذي يولّده Supabase عند إعداد HTTPS Hook. يُحفظ في Replit Secrets فقط، ولا يوضع في متغير EXPO_PUBLIC أو داخل التطبيق.
- EMAIL_HOOK_SENDER_ID: الرقم التعريفي للمرسل المفعّل في Brevo.
- EMAIL_HOOK_REDIRECT_URLS: قائمة JSON تحتوي روابط auth-callback المسموح بها حرفيًا. تستخدم لاستعادة كلمة المرور والدعوات وتغيير البريد. يجب أن تطابق إعداد URL Configuration في Supabase. أضيفوا رابط نسخة الجوال الفعلية عند اختبارها، ولا تستخدموا أنماطًا عامة.
- EXPO_PUBLIC_SUPABASE_URL: رابط المشروع نفسه الذي يصدر طلبات الـHook.

مثال غير سري لقائمة الروابط:

```json
["https://YOUR-VERIFIED-APP-URL/auth-callback","masarak://auth-callback"]
```

## ترتيب الإعداد الآمن

1. احتفظوا بالـHook معطّلًا أثناء الإعداد. لا تغيّروا طريقة الإرسال القائمة قبل نجاح الاختبار.
2. في Supabase: Authentication → Hooks → Send Email، اختاروا HTTPS. ولّدوا signing secret واحفظوه مباشرةً في Replit Secrets تحت SEND_EMAIL_HOOK_SECRET. لا ترسلوا المفتاح في المحادثة أو الصور.
3. اضبطوا رقم المرسل وقائمة الروابط. الخادم يبقى مغلقًا أمام طلبات الإرسال عند نقص أي إعداد.
4. شغّلوا npm run test:email-hook. للتجربة المحلية: PORT=3001 npm run email-hook.
5. إعداد نشر الخادم فقط: التثبيت npm ci ثم npm --prefix server ci، والتشغيل node server/email-hook-server.mjs. لا يشغّل Expo ولا ينشر تطبيق الجوال. راجعوا تكلفة تشغيل الخادم قبل الموافقة على نشره.
6. بعد نشره، احصلوا على عنوانه الحقيقي من صفحة النشر. URI للـHook هو عنوان الخادم متبوعًا بـ /api/auth/send-email. لا تختلقوا رابطًا ولا تستخدموا رابط المعاينة.
7. تأكدوا أن /health يعرض configured: true، ثم اختبروا رسالة فعلية من Supabase. لا يثبت فحص health وحده صلاحية توقيع الطلبات أو وصول البريد.
8. فعّلوا الـHook بعد الإعداد. أبقوا مزود Email وConfirm email مفعّلين، واجعلوا طول رمز Email OTP مساويًا لـ6. قوالب Supabase وSMTP لا تُستخدم لإرسال البريد عندما يتولى الـHook الإرسال.
9. اختبروا حسابًا غير مؤكد، رمزًا خاطئًا وصحيحًا، إعادة الإرسال، واستعادة كلمة المرور. تحققوا من البريد غير المرغوب أيضًا. عند عطل الإرسال عطّلوا الـHook لإعادة Supabase إلى مسار SMTP السابق؛ قد يعود قالب الرابط الافتراضي، فلا تعتبروا ذلك اختبارًا ناجحًا للرمز.

## حدود التحقق والأمان

- مكتبة standardwebhooks تتحقق من توقيع كامل الجسم ومن عمر الطلب. تعديل الجسم أو التوقيع أو الوقت يرفض الطلب قبل إرسال أي رسالة.
- حد الجسم 64 KiB، ولا يقبل الإرسال إلا POST JSON. الردود لا تكشف بيانات المستخدم أو الرموز أو رسائل Brevo الخام.
- مفتاح IdempotencyKey ثابت لكل طلب ومستلم؛ يمنع Brevo تكرار الرسالة عند إعادة محاولة الطلب خلال فترة احتفاظه بالمفتاح. ليس لدينا سجل دائم خاص بنا، ولا ندّعي تنفيذًا مرة واحدة إلى الأبد.
- مهلة انتظار Brevo أربع ثوانٍ. فشل الشبكة أو الحصة أو الإرسال يرجع خطأ، لا نجاحًا وهميًا. قد يكتمل إرسال طلب متأخر لدى المزوّد بعد انتهاء الانتظار؛ تبقى إعادة المحاولة بنفس مفتاح منع التكرار.
- لا تُسجّل أجسام الـHook أو الرموز أو الروابط أو الأسرار. سجلات مزوّد البريد لها سياسات احتفاظ مستقلة.
- الإرسال من إيميل مجاني عبر Brevo قد يستبدل عنوان المرسل بعنوان تابع له. هذا مناسب للتجربة المحدودة، وليس إعلانًا عن جاهزية النشر العام؛ يلزم مراجعة الدومين والتوثيق والتسليم الفعلي.
- الاختبارات المحلية لا تثبت تفعيل الـHook المستضاف أو وصول البريد إلى الصندوق الوارد.
