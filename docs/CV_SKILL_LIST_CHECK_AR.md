# إصلاح قوائم المهارات — 2026-10-21

## أدوار NLP وLLM وML بالنسبة للتقرير
- التقرير يبقى المرجع؛ هذا السجل يبين التنفيذ والفجوات ولا يعدّل التقرير ليلائم النقص.
- **NLP لاستخراج البيانات المنظمة (2.2.3 و4.2): منفذ جزئيًا.** المسار الفعلي يبدأ باستخراج نص PDF وتخطيطه، ثم يستخدم LLM عند تهيئته لفهم النص وإرجاع الحقول المنظمة. بعد ذلك تفحص قواعد الخادم الأقسام والأدلة والمخطط وتستكمل العناصر المذكورة حرفيًا. استخراج نص PDF وحده ليس دليل تنفيذ NLP كامل، ولا يوجد هنا نموذج NLP محلي مستقل مدرّب.
- **external LLM-based API لاستخراج المهارات (3.3.1): الربط الفعلي موجود.** `server/cv-app.mjs` يتحقق من الجلسة والموافقة ثم يمرر مفتاح الخادم إلى `analyzeText`؛ وجود المفتاح يستدعي Groq بالنموذج الموجود والمخطط التفصيلي، قبل التحقق واستكمال القوائم. إصلاح المهارات لا يستبدل هذا المسار بالقواعد.
- **القواعد:** معالجة تنسيق، تحقق من الدليل والبنية وربط قاموسي حرفي واستكمال مهارات صريحة. عند غياب المفتاح فقط يعمل التحليل المحلي المحدود المعلن؛ أخطاء المزوّد لا تتحول بصمت إلى نجاح محلي. ليس ذلك بديلًا مطابقًا لكل متطلبات التقرير.
- **ML مستقل مدرّب للتوصيات (2.2.2): غير منفذ في المسار الحالي.** `calculateCareerScore` يحسب نسبة أوزان المتطلبات الأساسية المطابقة إلى مجموع أوزانها، و`getCareerMatches` يرتب النسب. هذا ترتيب موزون كما في مفهوم 4.5.1، وليس دليل تدريب ML أو تحليل أنماط متعلّم. لا توجد في مسار التوصية المفحوص عملية تدريب أو استدلال بنموذج توصيات مستقل.
- تبقى فجوة ML ظاهرة؛ لا تدريب جديد ولا بيانات تدريب مختلقة ضمن هذا الإصلاح. اختبار الاتصال الحقيقي السابق استخدم عينة تركيبية مختلفة؛ مقتطف المهارات الحالي اختُبر محليًا وبمحاكاة المزوّد فقط ولم يُرسل للخارج.

## السبب المثبت
- أُعيد إنتاج المشكلة بالنص المنزوع من الهوية وPDF تركيبي يحتفظ بالشرطة والتفاف السطر؛ لم يُستخدم ملف المستخدم الأصلي.
- استخراج PDF احتفظ بكل النص. قبل الإصلاح أعاد المحلل المحلي 11 اسمًا غير صحيحة كمجموعة: أسقط Python وLinked List وSQLite وNetBeans وAlgorithms عندما التصقت بعناوين التصنيفات، وفصل Object-Oriented عن Programming.
- استعادة القوائم القديمة قبلت عناوين مع colon فقط وبداية السطر؛ أعادت صفر عناصر من هذه العينة ذات الشرطات والعناوين المتعددة.
- التحقق من وجود الاسم في النص وحده لا يميز عنوان تصنيف عن عنصر أو شظية من مصطلح كامل. لا يوجد رد Groq الأصلي لهذه المحاولة في أدلة الفحص، ولم تُنسب إليه المشكلة افتراضًا.

## الإصلاح المحدود
- قارئ مشترك لبنية القوائم: يقرأ قيم العناوين المتعددة في السطر مع colon أو شرطة مفصولة بمسافات، ويدعم العناوين المنفردة بحسب السياق.
- Databases عنوان حين يسبق قيمه بفاصل، لكنه يبقى مهارة عند وروده قيمة ضمن Concepts؛ لا توجد قائمة منع عالمية لأسماء التصنيفات.
- يحفظ المصطلح المركب في التفاف قائمة مسماة غير منتهية، دون تقسيم الكلمات على whitespace أو hyphen أو إسقاط +/#. لا يدمج بنودًا مستقلة أو يعبر أعمدة PDF أو حدود الأقسام.
- يوازن رد المزوّد مع العناصر الحرفية: يستعيد الأسماء المسقطة بأدلتها، ويزيل العناوين والشظايا عندما لا تكون عناصر مستقلة. Programming مستقلة تبقى مهارة.
- تبقى الأسماء الحرفية مستقلة عند اشتراكها في معرف قاموسي واحد؛ الربط لا يحوّل Python وJava وC++ إلى اسم واحد أو يضاعف معرفات التوصيات.
- تغير إصدار المحلل، فتستخدم النتائج السابقة تنبيه وإجراء إعادة التحليل الموجودين؛ لا يُكتب فوق اعتماد المستخدم تلقائيًا.

## التحقق والنتيجة
