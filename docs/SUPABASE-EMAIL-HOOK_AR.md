# دالة بريد مسارك داخل Supabase

هذا هو المسار المعتمد لتجربة تأكيد التسجيل برمز من 6 أرقام، دون نشر تطبيق الجوال أو خادم Replit. تشغيل هذه الدالة خدمة سحابية مستقلة داخل Supabase؛ لا يعني جاهزية مسارك للنشر.

## 1. المفاتيح والإعدادات في Supabase

افتح مشروع مسارك → **Edge Functions → Secrets**. احفظ الإعدادات التالية:

| الاسم | القيمة |
|---|---|
| `BREVO_API_KEY` | مفتاح API من **نفس حساب Brevo** الذي ربطناه. لا تستخدم SMTP password أو Supabase publishable key. |
| `SEND_EMAIL_HOOK_SECRET` | نفس مفتاح التوقيع الذي ولّدته في إعداد HTTPS Hook، كاملًا بما فيه `v1,whsec_`. حفظه في Replit وحده لا يوصله إلى Supabase. |
| `EMAIL_HOOK_SENDER_ID` | نفس الرقم الموجود في Replit Secrets؛ تحقق أن هذا المرسل مفعّل في حساب Brevo الخاص بالمفتاح. |
| `EMAIL_HOOK_REDIRECT_URLS` | قائمة JSON بروابط `auth-callback` الفعلية المسموح بها، المطابقة لإعدادات Supabase Auth. |

يمكن نسخ قيمة قائمة الروابط غير السرية من إعداد Replit الحالي `EMAIL_HOOK_REDIRECT_URLS`. رابط المعاينة مناسب لاختبار الاستعادة على الويب فقط؛ لا يعني أنه رابط نشر للتطبيق. رابط نسخة الجوال الفعلية يجب إضافته عند اختبارها. لا تستخدم wildcard.

لإنشاء مفتاح Brevo: افتح Brevo → SMTP & API → API Keys، واستخدم أو أنشئ مفتاحًا من الحساب نفسه. احفظه مباشرة في Supabase Secrets، وليس في المحادثة أو الكود أو `EXPO_PUBLIC_*`.

**لا تضف `SUPABASE_URL` يدويًا:** Supabase يوفره للدالة تلقائيًا. الدالة لا تحتاج service-role key ولا وصولًا لقاعدة البيانات.

استخدم مفتاح التوقيع الموجود دون تغييره أو توليد بديل. انسخه بنفسك من Replit Secrets إلى Supabase Secrets وإعداد الـHook. لا تستخرج مفاتيح ربط Replit أو ترسلها في المحادثة.

## 2. تجهيز الكود

المصدر الأساسي:

- `supabase/functions/send-auth-email/index.ts`
- `supabase/functions/send-auth-email/handler.ts`
- `supabase/functions/_shared/auth-email-templates.ts`

نسخة الملف الواحد لمحرر Supabase تُجهّز بالأمر:

```sh
npm run build:edge-email-hook
```

ثم افتح `generated-artifacts/send-auth-email/index.ts` من الملفات، وانسخ محتواه **كاملًا**. لا تعدّل النسخة المولّدة يدويًا.

في Supabase → **Edge Functions → Deploy a new function → Via Editor**:

1. سمّ الدالة `send-auth-email`.
2. استبدل محتوى `index.ts` بالكامل بالكود المجهّز.
3. اضغط **Deploy function**. هذا تشغيل للدالة فقط، وليس نشر تطبيق مسارك.
4. افتح إعدادات هذه الدالة، وأوقف **Verify JWT / Enforce JWT verification** لهذه الدالة وحدها. Supabase Auth يوقّع طلب الـHook، لكنه لا يرسل JWT مستخدم. الدالة نفسها تتحقق من التوقيع ووقت الطلب؛ إيقاف فحص JWT لا يلغي هذه الحماية.

إذا كانت الدالة موجودة سابقًا، لا تستبدلها دون فحصها. استخدم الاسم المذكور فقط، ولا تعدّل وظائف أخرى.

بديل للمطور الذي يملك CLI مصرحًا له:

```sh
supabase functions deploy send-auth-email --project-ref YOUR_PROJECT_REF --no-verify-jwt
```

لا تشارك access token أو بيانات تسجيل الدخول. نشر التطبيق في Replit ليس مطلوبًا لهذا المسار.

## 3. الفحص قبل إنشاء الـHook

- استدعاء POST غير موقّع يجب أن يعطي `401` من الدالة. `503` يعني إعدادًا ناقصًا أو غير صالح.
- لا تعتمد على `401` وحده: إن كانت استجابة البوابة تقول Missing authorization header، فهذا يعني أن فحص JWT لم يُعطّل لهذه الدالة. استجابة الحماية الخاصة بنا تقول `Invalid webhook signature.`.
- طلب GET يعطي `405`؛ هذا ليس فشلًا في الدالة.
- يمكن اختبار الإرسال قبل تفعيل الـHook بطلب يحمل توقيعًا صحيحًا بنفس المفتاح الموجود، إلى بريد تملكه فقط. لا تسجّل محتوى الطلب أو الرموز في Logs. رمز الاختبار ليس مرتبطًا بحساب ولا يمكن استعماله لتأكيد حساب.
- نجاح التشغيل والفحوص المحلية ليس دليلًا على تسليم الرسالة من Brevo. افحص الدالة المنشورة وأرسل رسالة اختبار قبل تفعيل الـHook:

```sh
node scripts/check-email-hook.mjs
node scripts/check-email-hook.mjs --remote
node scripts/check-email-hook.mjs --remote --send YOUR_OWNED_EMAIL
```

الفحص الأول يقرأ Replit Secrets ويختبر التوقيع وروابط الرجوع دون طباعة قيم الأسرار أو إرسال بريد. الثاني يتحقق من رفض الدالة المنشورة للطلب غير الموقّع. الثالث يرسل رسالة فعلية واحدة بطلب موقّع. يلزم تأكيد وصول الرسالة أو مراجعة سجل التسليم في Brevo قبل التفعيل. أسرار Replit لا تنتقل تلقائيًا إلى Supabase؛ انسخ الإعدادات الأربعة هناك بنفس القيم.

## 4. الآن فقط: Create hook

بعد التحقق من الدالة والإعدادات:

1. افتح **Authentication → Hooks → Send Email**.
2. اختر **HTTPS**.
3. انسخ عنوان الدالة من صفحة الدالة نفسها إلى **URL**. عنوانها ينتهي بـ `/functions/v1/send-auth-email`؛ ليس رابط SQL Editor أو Supabase Dashboard أو Replit Preview.
4. استخدم **نفس Secret** المحفوظ في Supabase Secrets، بدون توليد مفتاح مختلف.
5. فعّل **Enable Send Email hook** واضغط **Create hook**.

تفعيل الـHook يستبدل تسليم البريد الافتراضي. لا تفعلوه قبل الإعداد؛ فشل الدالة قد يمنع التسجيل وإعادة الإرسال واستعادة كلمة المرور.

## 5. اختبار واقعي

ابقِ **Confirm email** مفعّلًا، واضبط طول email OTP على 6 أرقام. لا تتجاوز التأكيد للتجربة.

اختبر حساب تجربة ببريد تملكونه:

1. إنشاء الحساب: تصل رسالة عربية برمز من 6 أرقام، وليس رابط تأكيد.
2. رمز خاطئ لا يؤكد الحساب؛ الرمز الصحيح يكمل التأكيد لدى Supabase.
3. إعادة الإرسال مع الانتظار ومراعاة حد الخدمة.
4. تسجيل الدخول المعتاد يبقى كلمة مرور، وليس OTP في كل مرة.
5. استعادة كلمة المرور: رسالة رابط تستمر بالعمل، ثم تغيير كلمة المرور وتسجيل الدخول.

لا تُعلن نجاح وصول الرسائل من مجرد HTTP 201؛ تحقق من صندوق الوارد/الرسائل غير المرغوب فيها أو سجلات Brevo. لا ترسل كلمات المرور أو الرموز في صور.

## حدود التشغيل والأمان

- التوقيع يُتحقق منه على نص الطلب الأصلي قبل استخدام محتواه. طلبات قديمة أو متلاعب بها تُرفض.
- حد الطلب 64 KiB، وتوجد مهلة قراءة ومهلة إرسال؛ فشل المزوّد يُرجع خطأ واضحًا لا نجاحًا وهميًا.
- عنوان Brevo ثابت؛ مفاتيحه لا تُرسل لعنوان يحدده محتوى الطلب. إعادة التوجيه HTTP غير مسموحة.
- مفتاح idempotency ثابت لكل حدث/مستلم، ضمن مدة دعم Brevo، وليس ضمانًا دائمًا للإرسال مرة واحدة.
- مهلة الإرسال تلغي الاتصال قدر الإمكان، لكن المزوّد قد يكون استلم الرسالة بالفعل؛ إعادة المحاولة تستعمل نفس مفتاح idempotency.
- تدعم الدالة التسجيل والاستعادة وتغيير البريد وإعادة التحقق والدعوات وروابط الدخول. لا تفعّلوا إشعارات أمان إضافية غير مدعومة دون إضافة دعمها واختبارها.
- المرسل الحالي مناسب للتجربة، لا دليل على جاهزية التسليم الإنتاجي لكل Gmail/Outlook أو اجتياز فلاتر Spam. حدود خطة Brevo وSupabase وسياسة المرسل تحتاج مراجعة قبل الإطلاق.
- تعطيل JWT خاص بهذه الدالة فقط. لا تغيّر RLS ولا سياسات الجداول أو تسجيل الدخول.
- لا تنشر خادم Replit، ولا تفعل الـHook قبل اختبار جاهزيته. الموبايل ما زال يحتاج اختبارًا فعليًا مستقلًا.
