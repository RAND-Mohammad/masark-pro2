# خادم مسارك: السيرة والمقابلة والدردشة المهنية

## المسار الحالي

يتحقق الخادم من جلسة Supabase وموافقة المستخدم وصحة ملف PDF. يقرأ PDF.js النص والتخطيط في ذاكرة الخادم، ثم يرسل **النص المستخرج فقط** إلى Groq. يستخدم نموذج `openai/gpt-oss-120b` افتراضيًا مع JSON Schema صارم. بعد الرد، يتحقق الخادم من البنية والاقتباسات والحقول والتواريخ قبل عرض مسودة المراجعة. يراجع المستخدم النتيجة ويعتمدها بنفسه.

- المفتاح: `GROQ_API_KEY`، سرّ خادمي مشترك بين تحليل السيرة وتوليد/تقييم أسئلة المقابلة والدردشة المهنية. كل ميزة مستقلة ولها موافقتها الصريحة.
- نموذج السيرة: `GROQ_CV_MODEL=openai/gpt-oss-120b`. نموذج المقابلة: `GROQ_INTERVIEW_MODEL=openai/gpt-oss-20b`؛ يدعم `GROQ_MODEL` القديم كخيار احتياطي.
- توليد الأسئلة يرسل المسار ونوع التدريب فقط بعد موافقة مستقلة. تقييم الإجابة يرسل نص الإجابة والسؤال ومفاهيمه المرجعية بعد موافقة أخرى؛ لا يُرسل التوليد السيرة أو بيانات الحساب إلى Groq.
- ملف التحليل: PDF نصي باللغة الإنجليزية فقط، حتى 10MB و15 صفحة و24,000 حرف مستخرج. الصور وOCR وWord غير مدعومة.
- عند غياب المفتاح أو فشل Groq أو عدم صلاحية الرد، يظهر خطأ واضح دون استبدال صامت بتحليل AI محلي.
- لا يُرسل ملف PDF نفسه إلى Groq؛ بعد موافقة المستخدم يرسل الخادم النص المستخرج فقط. لا تسجل الخدمة محتوى السيرة أو المفتاح.

## تدريب المقابلة

- `GET /interview/questions` يعرض أسئلة تدريب منتقاة محليًا للمسار المختار.
- `POST /interview/generate` يولّد ثلاثة أسئلة تقنية أو سلوكية للمسار بعد موافقة مستقلة. يرسل التطبيق المسار ونوع التدريب فقط، ولا يرسل السيرة أو نص الإجابة.
- `POST /interview/evaluate` يقيم الإجابة محليًا افتراضيًا. خيار Groq يتطلب موافقة أخرى ويرسل نص الإجابة وسؤال التدريب ومفاهيمه المرجعية. الأسئلة المولدة مرتبطة بجلسة المستخدم ومؤقتة على الخادم.
- التوليد محدود بثلاث طلبات في الدقيقة لكل حساب؛ لا تُحفظ الإجابات في سجلات الخادم. سجل النتائج يبقى في مساحة بيانات المستخدم كما في الإعداد الحالي.

## تصدير البيانات وحذف الحساب

- تصدير JSON يتم على الجهاز ويضم بيانات الملف والمهارات والخطة والتقدم وسجل المقابلات والوظيفة المحفوظة. لا يضمّن ملف السيرة PDF الأصلي.
- `POST /account/delete` يحتاج جلسة Supabase موثقة وتأكيدًا من شاشة الحذف. يحذف الخادم ملفات الحساب من `masarak-cvs` أولًا، ثم يحذف مستخدم Auth باستخدام مفتاح الخدمة السري. مفتاح `SUPABASE_SERVICE_ROLE_KEY` يبقى في `server/.env` أو مدير أسرار الخادم ولا يوضع في Expo.
- قبل تفعيل المسار، طبّق `supabase/001_account_cloud.sql` و`supabase/004_admin_console.sql` ثم `supabase/005_account_erasure.sql` و`supabase/006_admin_resource_link_check.sql` و`supabase/007_admin_job_schedule.sql`. يقفل 005 مزامنة الحساب على بقية الأجهزة أثناء الإزالة، ويمنع الجلسات القديمة من الوصول بعد حذف المستخدم؛ ويضيف 006 فحص نشر روابط الموارد، ويحفظ 007 جدول التحديث الإداري.
- نسخ قواعد البيانات الاحتياطية وسجلات الخدمة تخضع لسياسات الاحتفاظ لدى مزوديها؛ حذف التطبيق لا يغيّر تلك السياسات.

تدعم Groq JSON Schema الصارم لنموذج `openai/gpt-oss-120b` بحسب [الوثائق الرسمية](https://console.groq.com/docs/structured-outputs). تعرفي على معالجة البيانات في [وثائق Groq](https://console.groq.com/docs/your-data). لا توجد حصة مضمونة؛ قد يظهر تجاوز حد الاستخدام المؤقت برسالة واضحة.

## تشغيل محلي

1. ثبّت Node.js ثم شغّل `npm ci` و`npm --prefix server ci`.
2. انسخ `.env.example` إلى `.env` وأدخل إعدادات Supabase.
3. انسخ `server/.env.example` إلى `server/.env`، ثم أضف المفاتيح السرية المطلوبة للميزات المستخدمة. `GROQ_API_KEY` لتحليل السيرة والمقابلة والدردشة بعد الموافقة، و`SUPABASE_SERVICE_ROLE_KEY` لحذف الحساب ولوحة الإدارة. لا ترسل مفتاح Supabase السري إلى التطبيق.
4. من مجلد المشروع على Windows شغّل `npm.cmd start`؛ يبدأ Expo وخادم Node.js معًا، ويعيد استخدام الخادم إذا كان يعمل على المنفذ 3001. لتشغيل الخادم وحده استخدم `npm.cmd run cv-server`. عند التجربة على الجوال، وصّل الجوال والكمبيوتر بالشبكة نفسها.
5. جرّب بحساب مصرح وPDF اصطناعي أو منقح فقط، ثم راجع الأدلة والحقول في التطبيق.

لا تحفظ ملفات `.env` أو مفاتيح API في Git. لا تضع المفتاح داخل التطبيق أو متغير `EXPO_PUBLIC_`. مفتاح Gemini لم يعد مطلوبًا لتحليل السيرة. نقل التعديلات إلى جهاز آخر لا ينقل المفتاح؛ أضيفوه منفصلًا في بيئة الخادم.
